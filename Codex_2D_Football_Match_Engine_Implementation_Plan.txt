CODEX AI IMPLEMENTATION PLAN
2D FOOTBALL MATCH ENGINE - PLAYER AI, TEAM SHAPE, MOTION FLOW, DECISION MAKING

PROJECT CONTEXT
We already have:
- a working 2D football pitch prototype,
- player icons that can move,
- ball movement,
- initial match tests,
- player attributes,
- tactical settings.

The current problem is that the match engine is too chaotic.
Players move without clear football logic, chase the ball too often, lose formation shape, and do not react intelligently to the current phase of play.

The goal is NOT to rewrite the whole project from scratch.

The goal is to refactor the current prototype step by step into a modular 2D football AI system where:
- every player has a role,
- every player has a formation reference point,
- every player has a current state and movement intention,
- players react to the ball, teammates, opponents, tactics and current match phase,
- players with the ball can decide whether to pass, carry, dribble, shoot, cross, play backwards, switch play, etc.,
- players without the ball make logical support runs, defensive movements, pressing movements and recovery runs,
- the whole team moves as a coordinated unit,
- decisions are based on player attributes and tactical instructions,
- movement remains suitable for a simple 2D visualization and does not require advanced body physics.

IMPORTANT DEVELOPMENT RULES

1. First inspect the existing codebase.
2. Identify the current player movement, ball movement, formation, AI and match-loop systems.
3. Do not create a second parallel match engine if the existing systems can be refactored.
4. Reuse existing data structures and components where practical.
5. Implement this in stages.
6. After every stage, create a debug/test scenario.
7. Do not continue to the next major stage until the previous stage behaves correctly.
8. Add debug visualization early.
9. Keep decision logic separate from movement logic.
10. Keep team-level tactical logic separate from player-level decision logic.
11. Avoid hard-coded scripted movement for normal open play.
12. Action scripts can later be used for highlights, set pieces and special events, but they must not control the entire match.

PHASE 1 - NORMALIZED PITCH COORDINATE SYSTEM
==================================================

GOAL
Make all tactical logic independent of screen resolution.

IMPLEMENTATION
Use normalized pitch coordinates internally.

Example:
X = 0 to 100 along pitch length.
Y = 0 to 100 across pitch width.

One team attacks toward X=100.
The other attacks toward X=0.

Rendering code converts normalized coordinates into screen pixels.

Each player should expose at minimum:
- currentPosition
- currentVelocity
- currentTarget
- formationAnchor
- roleZone
- currentState
- currentIntent
- teamId
- role
- possessionState

TEST
Create a debug overlay displaying X/Y coordinates.
Move players to several normalized locations.
Resize the pitch UI if supported.

SUCCESS CONDITION
Football logic works independently of actual screen dimensions.

PHASE 2 - FORMATION ANCHORS AND ROLE ZONES
==================================================

GOAL
Stop random wandering.

Start with only:
4-4-2 vs 4-4-2.

Each role must have:
- formationAnchor,
- allowed role zone,
- minimum/maximum forward displacement,
- minimum/maximum lateral displacement.

Example concept:
GK
LB - CB - CB - RB
LM - CM - CM - RM
ST - ST

A formation anchor is NOT a fixed position.
It is a reference point.

Target position should later be calculated approximately as:

targetPosition =
formationAnchor
+ ballPositionShift
+ teamShapeModifier
+ tacticalModifier
+ currentIntentModifier

IMPLEMENTATION
Create formation definitions as data, not hard-coded movement logic.

TEST
Disable ball actions and player decision AI.
Move a fake ball position manually around the pitch.

The formation should:
- shift toward the ball,
- move higher when the ball moves forward,
- move lower when the ball moves backward,
- stay compact,
- never collapse onto the ball.

SUCCESS CONDITION
The team visibly moves as one coordinated block.

Do not continue until this looks correct.

Each team phase modifies formation anchors and tactical priorities.

Examples:

DEFENSIVE_SHAPE
- defensive line lower,
- midfield closer to defence,
- forwards slightly deeper,
- compact width.

BUILD_UP
- defenders spread slightly,
- midfield creates passing options,
- fullbacks can widen.

ATTACK
- forwards higher,
- wingers wider or more advanced,
- midfield support moves forward.

FINAL_THIRD
- attacking players enter dangerous zones,
- defensive cover remains behind the ball.

TRANSITION_ATTACK
- forward runs receive temporary priority.

TRANSITION_DEFEND
- recovery and pressing receive temporary priority.

SUCCESS CONDITION

PHASE 4 - MOTION ENGINE
==================================================

GOAL
Separate "where the player wants to go" from "how the player gets there".

DECISION AI MUST NOT directly manipulate coordinates every frame.

Player AI assigns:
- intent,
- target position,
- desired speed.

Motion Engine executes movement.

Motion Engine should initially support:
- walking/jogging/running speed,
- smooth acceleration/deceleration,
- stopping near target,
- pitch boundary constraints,
- simple player separation,
- no teleporting,
- no excessive jitter.

Use player attributes where appropriate:
- SPEED influences maximum movement speed,
- CONDITION may later affect speed,
- WORK_RATE may affect activity frequency.

Avoid advanced physics.

TEST
Give different players manual targets.
Run all 22 players simultaneously.

SUCCESS CONDITION
Movement is smooth, stable, deterministic enough for debugging, and players do not oscillate around targets.

PHASE 8 - UTILITY AI FOR THE BALL CARRIER
==================================================

GOAL
The player with the ball chooses between meaningful actions.

Initial actions:

PASS
CARRY
SHOOT
PASS_BACK

Later add:
THROUGH_PASS
DRIBBLE
CROSS
LONG_PASS
SWITCH_PLAY
HOLD_BALL

Each possible action receives a Utility Score.

Example concept:

SHOOT =
FINISHING
+ TECHNIQUE
+ MENTALITY
+ shootingPositionQuality
+ goalVisibility
- distancePenalty
- defensivePressure

PASS =
PASSING
+ VISION
+ TECHNIQUE
+ bestPassOption
+ tacticalPreference
- interceptionRisk

CARRY =
DRIBBLING
+ TECHNIQUE
+ SPEED
+ availableSpace
- pressure
- nearbyDefenders

PASS_BACK =
pressure
+ lackOfForwardOptions
+ tacticalSafety
+ mentalityModifier

Do not use purely deterministic choice.

Use small controlled randomness after scoring, for example:
finalScore = utilityScore * random factor approximately 0.90-1.10

The random factor should be configurable.

IMPORTANT
Do not recalculate decisions every rendered frame.

Use a decision interval such as approximately 300-700 ms, influenced later by context and mental attributes.

Add decision commitment so a player does not repeatedly change his mind during the same action.

TEST
Create controlled situations:
1. open shot,
2. obvious forward pass,
3. heavy pressure,
4. no forward option,
5. open space to carry.

SUCCESS CONDITION
The chosen action is usually football-logical while still allowing occasional variation.

PHASE 12 - TACTICAL MODIFIERS
==================================================

GOAL
Tactics influence decisions rather than directly scripting movement.

Connect existing tactical settings.

Examples:

TEMPO
Fast:
- forward pass score increases,
- forward carry increases,
- decision interval can become slightly shorter,
- pass-back preference decreases.

Slow:
- support and safe passing increase,
- risky forward actions decrease.

MENTALITY
Cautious:
- safer passes,
- more support behind ball,
- fewer risky runs,
- lower defensive line.

Aggressive:
- forward runs,
- pressure,
- attacking numbers,
- higher risk.

PRESSING
ON:
- PRESS_BALL utility increases,
- defensive recovery behavior changes.

COUNTERATTACK
ON:
- forward run utility increases after recovery,
- through-ball preference increases,
- slow build-up preference decreases.

PASSING STYLE
Short:
- short/medium passing options receive bonuses.

Direct:
- forward/long passing receives bonuses.

TACTICAL SETTINGS MUST MODIFY SCORES AND SHAPE.
They should not force identical scripted sequences.

TEST
Run the same teams repeatedly with:
1. cautious/slow/no press,
2. aggressive/fast/high press,
3. counterattacking.

SUCCESS CONDITION
The difference should be clearly visible even before looking at statistics.
